# DATA_CONTRACT - standard quarter-hourly upload (D-TPL) and importer (D-IMP)

Version ESB-STD-QH 1.1 (16.09.2026, D112; 1.0 files remain accepted) - Phase 2 (`GW-ESB-01` / `T12.2`). Derived from the nextE data
time-series standard template v1.0 (25.08.2026, `STD_EET_QH`), reduced to what the engine needs
and made explicit where the Excel template left things implicit.

## 1 Purpose

Every quarter-hourly series the engine consumes - off-taker consumption, PV generation,
Baseload nominations, wholesale and imbalance prices - enters through one upload workbook per
input class and spine year. The workbook declares itself completely (control block, series
registry, raw values); the importer validates it, brings it onto the engine grid, runs six
binding checks and refuses on any failure. Nothing is inferred, nothing is filled.

## 2 Workbook layout

| Sheet | Content |
|---|---|
| `Instructions` | text for the person filling the file |
| `Std_Control` | key / value: `template_version`, `input_class`, `spine_year`, `intervals_per_day` (96), `time_basis`, `offset_eet_cet_h` (1), `scenario`, `provider`, `delivery_date`, `notes` |
| `Series_Registry` | one row per slot: `slot`, `name`, `unit`, `class`, `spring_rule`, `autumn_rule`, `paired_volume_slot`, `k`, `basis`, `entity_code`, `required`, `notes`; 1.1 adds the optional `scenario_name` (wholesale files) and `entity_name` (reference only) |
| `RAW_EET_QH` | row 1 header `Date_EET, Start_EET, End_EET, E01, E02, ..., C01, ...`; data from row 2; values only |
| `Recon_Check` | convenience counts for the person filling the file; not binding |

Slots `E01`..`E40` carry numbers, `C01`..`C10` carry categories (1.1: any digit width, e.g.
`E0001`..`E1200`). A slot with data must be declared; a declared `required` slot must carry
data.

### 2.1 Version 1.1 (D112)

* `scenario_name` in the registry: a wholesale file may carry several scenario blocks (the same
  five series per scenario); series are keyed `scenario_name + name` and reach the engine as
  `<scenario>__<name>` frames; the application maps each block to a scenario of the register.
* `entity_name` (also accepted as `entity_name_reference`): the display name of the entity for
  the person filling the file; the importer never reads it into the engine (F-035).
* **Not delivered**: a declared slot whose RAW column is entirely blank is listed in
  `Provenance.not_delivered` and dropped from the registry and the frame instead of being
  refused. A partly blank column is still a gap and is refused. Under 1.0 the old behaviour holds.
* Templates are written as 1.1, sized to the register (one slot pair per off-taker, one block
  per scenario) in the CEO's canonical input styling (Montserrat, navy header, input cells
  `#FFFCEB`, unit-bearing number formats, `hh:mm` times, gridlines off, freeze `A2`).

Templates are generated by `esb.importer.build_template(input_class, spine_year, path)`; the
four blank templates for 2027 are delivered to the CEO folder (`00_Spec/01_current/input_data_template/`).

## 3 Input classes and their pre-declared registries

| input_class | slots | class / rules | k |
|---|---|---|---|
| `offtaker_load` | per off-taker code: `<OT>_metered_consumption_MWh`, `<OT>_notified_consumption_MWh` | Extensive, inject_zero / sum | -1 (DSO metering, consumption +) |
| `pv_generation` | `PV1_forecast_generation_uncurtailed_MWh` (Extensive); `PV1_forecast_generation_deviation_pct`, `PV1_imbalance_deviation_pct` (Intensive, interpolate / volume_weighted on E01) | | -1 on the volume slot |
| `baseload_nomination` | per off-taker code: `<OT>_BL24_nomination_MWh`, `<OT>_Peak_nomination_MWh`, `<OT>_OffPeak_nomination_MWh` (optional) | Extensive, inject_zero / sum | +1 (BRP) |
| `wholesale_prices` | `DAM_price_EUR_MWh`, `IDCT_VWAP15_price_EUR_MWh`, `Surplus_imbalance_price_EUR_MWh`, `Deficit_imbalance_price_EUR_MWh` (Intensive, interpolate / mean); `C01 System_imbalance_direction` (Categorical, optional) | | - |

Entities are referenced by code (`OT1`.. by merit-order position, `PV1`); names never enter a
template, a fixture or the repository. The Reference Case uses `OT1`..`OT4` and `PV1`.

Curtailed prices (`MAX(price, 0)`) and the active-scenario selection are derived by the engine
and are not uploaded.

## 4 Time basis

The engine grid is positional: 96 rows per calendar day, labelled in EET with a fixed one-hour
offset to CET (`esb.grid`). Two upload bases are accepted:

* `local_clock` - rows follow the real Romanian clock: the last Sunday of March has 92 rows
  (03:00-03:45 EET absent), the last Sunday of October has 100 rows (03:00-03:45 EET twice).
  The importer applies the registry rules to those eight intervals (section 5).
* `fixed_96` - rows are already 96 per day for every day. No rule is applied. This is the
  basis of every series inside the Reference Case workbook (SPEC section 4, ruling G0-D2).

A `local_clock` declaration on a file that actually has 96 rows on the transition days is
refused by the layout check (4 missing, 4 duplicated), and vice versa.

The workbook's fixed 35.136-row container (96 placeholder rows at 29.02 in the Reference Case;
96 `Outside` rows at the end of the STD template) is not part of the contract: a common year has
35.040 rows, a leap year 35.136, and every aggregation is keyed by date.

## 5 Rules on the daylight-saving intervals (`local_clock` only)

| class | spring (Injected, 4 intervals absent) | autumn (Merged, 4 intervals twice) |
|---|---|---|
| Extensive (energy per interval) | `inject_zero` -> 0 | `sum` |
| Intensive (price, ratio, power) | `interpolate` -> `v_prev + (v_next - v_prev) x j / 5`, j = 1..4, between the last value before and the first value after the gap; `locf` -> last value before the gap | `mean`; `volume_weighted` -> weighted by the two rows of `paired_volume_slot`, simple mean when the weights sum to 0 |
| Categorical | `carry_forward` -> last value before the gap | `first` |

These are the STD template's rules verbatim (dispatch formula of `STD_EET_QH`, read 14.09.2026).
Energy is conserved by construction and verified by check 5.

## 6 Sign convention `k`

Volume series declare `k` once: `-1` for the DSO metering convention (consumption +,
generation -), `+1` for the BRP imbalance convention (generation +, consumption -). The
importer records `k` in the provenance and never transforms a sign; the engine applies the
rule book (`esb.imbalance`) with the declared `k`. A volume series without `k` is refused.

## 7 The six checks

| # | name | FAIL when |
|---|---|---|
| 1 | spine | control block invalid: unknown input class, spine year out of range, intervals not 96, unknown time basis, offset not 1, template version not recognised, required sheet missing |
| 2 | layout | any (date, interval) delivered a different number of times than the time basis requires; rows outside the spine year; unreadable date or start time; empty surface |
| 3 | surface | a formula anywhere in `RAW_EET_QH`; an undeclared column carrying data; a non-numeric value in a numeric slot; header not `Date_EET, Start_EET, End_EET, ...` |
| 4 | registry | inconsistent declaration (class vs rules, unit, `k`, pairing), duplicate slot or name, required slot absent from the surface, no slot at all |
| 5 | energy | for any Extensive slot, the year sum or any daily sum of the standardised series differs from the raw rows by more than `1e-6 x max(abs(raw), 1)` |
| 6 | gaps | a blank cell inside a required series after standardisation (the importer never fills); blanks in optional series are counted and reported, not refused |

Rows out of chronological order are accepted and re-sorted (reported in check 2's detail).

## 8 Output

`import_workbook(path)` returns an `ImportResult`:

* `ok` - all six checks passed
* `checks` - the six `CheckResult`s (code, name, PASS / FAIL, detail, up to 50 items)
* `frame` - when accepted: the engine grid (`seq`, `date`, `interval`, `start_eet`, `end_eet`,
  `start_cet`, `month`, `weekday`, `peak`, `dst_status`) plus one column per slot *name*;
  blanks are `NaN`; categorical slots are strings
* `provenance` - filename, md5, size, template version, input class, spine year, time basis,
  scenario, provider, delivery date, the full registry, the `k` map, the import timestamp (UTC)
  and the check outcomes; `to_json()` for storage next to the imported data

## 9 Reference Case fixtures

`data/reference/rc_v03_series.parquet` holds every input series of the frozen Reference Case
workbook (`Energy_Supply_Portfolio_Tracking_v03_[base].xlsx`, md5
`1c873718bcd08957229f1f46d5449b2a`) on the engine grid, coded `OT1`..`OT4` / `PV1`, values
exactly as stored in the workbook, with `rc_v03_series_manifest.json` (column map, sums,
provenance). It was built by `tools/build_rc_fixtures.py` from cell-level extracts of the
sheets `FW_Retail_Volume`, `FW_Source_Purch_Volume` and `Whol_Sport_Imb_Fcst`; the build
asserts that the workbook's dates, interval positions and Peak flags equal the engine grid on
all 35.040 rows.

The same series exist as four `fixed_96` upload workbooks in the CEO folder
(`01_Tool/03_testdata/RC_v03_*.xlsx`); each was written by `write_delivery` and read back by
`import_workbook` with six PASS. Workbooks written by openpyxl carry 16 significant digits and
may differ from the parquet by one unit in the last place (relative 1e-16); Excel writes 17.

Not in the fixtures: the workbook's portfolio budget series `FW_Retail_Volume!AF:AG` (only used
to scale the placeholder off-takers, whose scaled series are extracted directly) and the values
the workbook carries on its 96 undated placeholder rows (prices; volumes are 0) - no date-keyed
aggregation reads them (X-29).

## 10 Gate G2 status

The importer reproduces the STD reconciliation logic on synthetic local-clock deliveries (unit
and edge suites, 2026-2028) and accepts the four Reference Case workbooks. No real supplier or
DSO delivery spanning a daylight-saving transition was available in Phase 2; the G2 criterion
"importer reproduces `Recon_Check_EET` on a real delivery" is therefore met on synthetic data
only and stays flagged until a real file is placed in `_sources/_internal/`.
